# 일정 카테고리 — 담당자 과제

> 경로·요청/응답은 정해주지 않는다. **설계해서 PM 확인받고 구현할 것.**

## 문제

`events.category` 가 varchar 자유 입력이라 관리자가 매번 손으로 친다.
→ 표기가 갈리고("정기모임"/"정기 모임"), 프론트가 카테고리 필터·색상 구분을 만들 수 없다.

## 이미 있는 것

- **`event_categories` 테이블 + 기본 카테고리 시드 적용 완료** (스키마·데이터는 DB에서 직접 확인)
- 일정 코드: `com/back/event/`(조회·공개), `com/back/admin/event/`(등록·수정·삭제)
- 현재 명세: `api_endpoints` 에서 `path LIKE '%event%'`

## 할 일

**A. 카테고리를 실제로 쓰이게 만들기** — 관리자는 목록에서 고르고, 프론트는 그 목록을 받아갈 수 있어야 한다.
- 목록 조회는 누가 볼 수 있어야 하는가 (공개? 관리자만?)
- 목록에 없는 값이 들어오면 어떻게 되어야 하는가. 검증은 어디서 하는가
- `events` 와 무엇으로 연결할 것인가 — 이름? 다른 방법? **고른 이유를 설명할 수 있어야 한다**
  (이미 `events.category` varchar 가 있다는 점, 카테고리 이름이 나중에 바뀔 수 있다는 점)
- 기존 일정들의 `category` 값은 어떻게 처리하는가
- 카테고리 추가·수정·숨김이 필요한가. 쓰이는 중인 카테고리를 숨기면 그 일정들은 어떻게 되는가

**B. 애매한 지점은 PM 에게 질문으로 가져올 것** — 혼자 결정해버리지 말 것.

## 규칙

`CLAUDE.md` 정독. 특히 — 소프트삭제 대전제(`is_active` 가 왜 있는지 생각할 것) /
관리 쿼리는 `admin.event` 소유, 공개용은 `event` / 경로에 신분 접두사 금지 /
`@Param` / 에러는 `{"message":...}` / 스웨거 문서화.
**DDL 추가가 필요하면 직접 적용하지 말고 PM 승인받을 것** (qa_pilsa 는 운영 DB, `.sql` 은 레포 미커밋).

## 참고

게시판에 이미 카테고리 개념이 있다(`categories` 테이블). 구조를 보고 가져올 부분을 판단할 것.
단 **그 테이블 자체를 일정에 재사용하지 말 것** — 게시판 전용(`board_id` 소속)이다.
