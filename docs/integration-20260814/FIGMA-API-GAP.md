## 🔴 스펙 충돌 — PM 결정 필요

### 1. 아이디 찾기: 시안은 "전화번호"도 받는다
- **시안**: "회원가입 시 등록했던 **전화번호나 이메일**을 입력해주세요" → 인증 → "**문자**를 발송했어요. 인증번호를 입력해 주세요"
- **API**: 이메일만 지원 (`POST /api/mail/verification-code` → `POST /api/auth/id/verify` → `GET /api/auth/id/find`)
- **문제**: SMS 발송 인프라가 없다. 전화번호 인증을 지원하려면 문자 발송 서비스 계약 + API 신설이 필요.
- **선택지**: ① 시안에서 전화번호 제거(이메일만) ② SMS 인증 도입(비용·API 신설)

### 2. 비밀번호 찾기: 시안 흐름에 loginId가 없다
- **시안**: "전화번호 혹은 본인 확인 이메일" **1개 입력** → 인증번호 → 새 비밀번호 입력
- **API**: `GET /api/auth/verification?loginId=...&email=...` — **아이디+이메일 둘 다** 필수.
  `PUT /api/auth/password/reset` 도 `{loginId, newPassword}` 로 **loginId 필수**.
- **문제**: 시안대로면 프론트가 loginId를 알 수 없어 마지막 재설정 호출 자체가 불가능.
- **선택지**: ① 시안에 아이디 입력 추가 ② API를 이메일 기반으로 변경(인증 완료 이메일 → 비밀번호 재설정, 아이디찾기의 Redis 1회성 패턴 재사용)

### 3. 마이페이지 "정보 수정" 모달: 현재 비밀번호 검증 요구
- **시안**: 비밀번호 수정 모달 — **현재 비밀번호** / 새 비밀번호 / 새 비밀번호 확인, 오류 상태로 "현재 비밀번호 불일치"·"새 비밀번호 불일치" 프레임 존재
- **API**: `PATCH /api/user/mypage/password/reset` (id=72, **planned·미구현**). 명세 요청 예시에 현재 비밀번호 검증이 없다면 시안과 어긋남.
- **필요**: 구현 시 요청을 `{currentPassword, newPassword}` 로 잡고 현재 비밀번호 불일치 시 400 메시지 반환.

## 🟠 API 도메인 자체가 없음

### 4. 활동 사진 페이지
- **시안**: 사이드바 메뉴 "활동 사진" + 전용 페이지(사진 그리드 갤러리, 기본/호버 상태, 모바일 버전까지 존재)
- **API**: 활동 사진 관련 엔드포인트가 **1기·2기·planned 어디에도 없다.**
- **필요(최소)**: 사진 목록 조회 1본 + (관리자) 업로드/삭제. 데이터 모델(전용 테이블 vs 게시판 활용) 결정 필요.

> 참고: 사이드바에 **"방명록"** 메뉴도 있으나, 게시판이 데이터(boards)로 정의되므로
> 관리자가 방명록 게시판을 생성하면 기존 `/api/user/boards/{boardId}/**` 로 동작한다. 신규 API 불필요.
